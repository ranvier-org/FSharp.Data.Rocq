# Prose syntax & Guarantees

Navigator renders documentation directly from `.v` comments—linking resolved symbol names to their declarations with hover cards, extracting structured binder descriptions, and curating titled theorems onto the site's **Guarantees** landing page.

## The three comment forms

| Opening Delimiter | Format | Rendered Output |
| :--- | :--- | :--- |
| `(** ... *)` | **Doc** | Headings (`*` to `****`), paragraphs, and `[code]` spans |
| `(**md ... *)` | **Markdown** | Full CommonMark (`#` headings, lists, emphasis, pipe tables, fenced code blocks, and `` `code` `` spans) |
| `(* ... *)` | **Plain** | Attached prose when immediately above a declaration; folded inline code comment when inside a sentence or proof |

### Doc comments (`(** ... *)`)

- One to four leading `*` characters followed by a space open a heading (`* H1` through `**** H4`).
- Consecutive lines join into paragraphs; blank lines separate paragraphs.
- Square brackets `[total]` mark inline code. When the bracketed identifier uniquely resolves to a symbol in scope (or in the current file), it becomes a link with a hover card; expressions like `[1 + 1]` remain plain code spans.
- Doc comments intentionally do not parse bullet lists (other than `- [arg:]` binder entries); use `(**md ... *)` for lists and tables.

### Markdown comments (`(**md ... *)`)

- Supports CommonMark headings (`#` through `######`), bulleted/numbered lists, pipe tables, external links, and fenced code blocks.
- Backticked identifiers (`` `total` ``) resolve to hover-card symbol links using the same scoping rules as `[total]` in doc comments, while identifiers inside fenced ```` ``` ```` blocks remain plain text.
- **Safety invariants** enforced across all comments:
  1. Raw HTML tags are escaped and rendered as literal text (Markdig extensions cannot re-enable raw HTML).
  2. Links with URI schemes other than `http`, `https`, or `mailto` (or relative `.html#anchor` module links) render as plain text.
  3. Cross-module links can be written as `[append](Core.html#append)` using either the full module name or a unique dotted suffix.

## Documenting declaration arguments (`- [name:]`)

In both `(** *)` and `(**md *)` comments attached to a declaration, lines matching `- [name:] description` (with optional indented continuation lines) document that declaration's binders:

```coq
(** Appends a count to the front of a tally.
    - [n:] the count added, whose description
      continues on an indented line.
    - [t:] the tally extended, mentioning [size]. *)
Definition push (n : nat) (t : tally) : tally := cons n t.
```

Navigator extracts these entries out of the prose paragraph, displays them in an **Arguments** list alongside the declaration, and attaches each description (plus its captured Gallina type when `facts.json` is supplied) to the binder's hover card. If `- [name:]` names an identifier that does not match any binder on the declaration, Navigator emits warning `rocq/argument-unmatched` (which fails `--strict` builds).

## Attached vs. free-standing comments

Walking backward from a declaration's or scope's first token, a top-level comment attaches to that declaration when:
1. At most **one newline** separates the comment from the declaration (or from the next attached comment below it), and
2. The comment does not sit on the trailing line of an earlier sentence.

Inserting a blank line between a comment and the following declaration detaches it so it renders as free-standing narrative prose between declarations. Comments inside a statement stay inline in the rendered code, and comments inside a `Proof ... Qed.` block fold and unfold together with the proof.

## Curating the Guarantees page

The root index page generated by Navigator summarizes what a Rocq project formally establishes without requiring readers to step through auxiliary lemmas.

### Promoting a theorem to Guarantees

A `Theorem` or `Corollary` (never a `Lemma`) appears on the **Guarantees** page when its attached `(**md ... *)` comment begins with a **first line written wholly in bold**, which becomes its human-readable guarantee title:

```coq
(**md
**Appending adds totals.**

The total of two tallies appended equals the sum of their totals.

- [a:] the counts that come first.
- [b:] the counts that come last.
*)
Theorem total_append (a b : tally) : total (append a b) = total a + total b.
Proof.
  induction a as [| n rest IH].
  - reflexivity.
  - simpl. rewrite IH. symmetry. apply add_regroup.
Qed.
```

### Guarantee classification groups

Each titled `Theorem` or `Corollary` is filed into the first matching group:

| Group | Rule | Meaning |
| :--- | :--- | :--- |
| **Open** | Proof ends with `Admitted` | Claim stated, proof not yet completed |
| **Falsified** | Name ends with `navigator.json`'s `falsifiedSuffix` (e.g. `_falsified`) | Proved counterexample refuting a candidate property |
| **Checks** | Attached comment contains `navigator.json`'s `checkMarker` (e.g. `@checked`) | Bounded or property-checked verification witness |
| **Guarantees** | Proved (`Qed` / `Defined`) and matches none of the above | Unconditional machine-checked theorem |

### Axiom & assumption badges

When `facts.json` is provided (`rocq-capture`), each proved entry in **Guarantees** and **Checks** displays an assumption badge derived from `Print Assumptions`:
- Theorems closed under the empty context (`Closed under the global context`) show that they depend on **no axioms**.
- Theorems resting on `Axiom`, `Parameter`, or `Context` assumptions list the exact assumptions used (for example, `Axiom counts_are_small`).
- **Open** and **Falsified** entries omit assumption verdicts because an admitted proof establishes nothing and a falsified theorem is an intentional refutation.
